## 1. 第一步：解决「npm 无法加载文件 npm.ps1，因为禁止运行脚本」

### 1.1 现象

```text
PS C:\Users\ccgg5\Desktop\wenya\frontend> npm
npm : 无法加载文件 C:\Program Files\nodejs\npm.ps1，因为在此系统上禁止运行脚本。
    + CategoryInfo          : SecurityError: (:) []，PSSecurityException
    + FullyQualifiedErrorId : UnauthorizedAccess
```

### 1.2 根因（本机实测）

`C:\Program Files\nodejs\npm` 是个 shell 脚本分发器：PowerShell 会去执行同目录的 `npm.ps1`，
而本机 PowerShell 的**生效执行策略是 `Restricted`**（默认连本地签名脚本都不允许），于是脚本被拦截。

```powershell
PS> $PSVersionTable.PSVersion   # 5  1  26100  9444   → Windows PowerShell 5.1
PS> Get-ExecutionPolicy         # Restricted          → 生效策略
PS> Get-ExecutionPolicy -List   # 五个 Scope 全部 Undefined → 没人显式设置过，走系统默认 Restricted
```

**这和 Node、npm、本项目都没有关系**，项目本身是正常的（用 `cmd.exe` 跑同样的命令完全没问题）。

### 1.3 三种解法，任选一种

**解法 A —— 改用 `npm.cmd`（零改动，立即生效，推荐先用这个）**

```powershell
npm.cmd install
npm.cmd run dev
npm.cmd run build
```

`.cmd` 是批处理文件，不受 PowerShell 执行策略约束。缺点：多打 4 个字符。

**解法 B —— 放开当前用户的执行策略（一次配置，以后 `npm` 直接能用）**

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

- 作用域 `CurrentUser` **不需要管理员权限**，只改你自己账户；如果想连其他账户一起修好，用 `-Scope LocalMachine`（需要管理员 PowerShell）。
- `RemoteSigned`：本地脚本直接放行，从网上下载的脚本需签名。这是 Node 开发机的常规设置。
- 撤销：`Set-ExecutionPolicy -Scope CurrentUser Undefined`。
- 该命令修改的是**你机器的系统配置**（不在项目目录内），请自己确认后再执行；如需临时放行而不改配置，也可以只开一个 bypass 会话：`powershell -ExecutionPolicy Bypass -NoExit`。

**解法 C —— 换用 `cmd.exe` 终端**

```cmd
cd /d C:\Users\ccgg5\Desktop\wenya\frontend
npm run dev
```

cmd 走的是 `npm.cmd`，同样不受执行策略影响。

> 本文余下部分统一写成 `npm.cmd xxx`。如果你按解法 B 配置过，把它读作 `npm xxx` 即可。

### 1.4 顺带一个 PowerShell 5.1 语法坑

PowerShell 5.1 **不支持 `&&`**（那是 PowerShell 7+ 才有的）。要连着执行命令请用分号或分行：

```powershell
npm.cmd run build ; npm.cmd run preview     # PS 5.1 可用
cd frontend && npm run build                # ❌ PS 5.1 报错，cmd.exe 里才可用
```

## 2. 项目结构与运行前提

### 2.1 技术栈（读自 `package.json` / `vite.config.js`）

| 项 | 值 |
| --- | --- |
| 框架 | Vue 3 + Vue Router 4（**history 模式**）+ Pinia |
| 构建 | Vite 5.4.21 + `@vitejs/plugin-vue` 4 |
| 样式 | Tailwind CSS 3.3 + PostCSS + Autoprefixer + Sass |
| 其他 | axios、ECharts / vue-echarts、Quill 1.3、Day.js、@vueuse/core |
| 路径别名 | `@` → `frontend/src` |

### 2.2 环境要求

- Node.js：本机实测 **v24.21.0**，npm **11.19.0**。Vite 5 的硬性下限是 Node 18 / 20+，低于 18 直接起不来。
- 系统：Windows（本文路径按 Windows 写；Linux/macOS 只需把 `npm.cmd` 改回 `npm`、路径换成 `/`）。

### 2.3 后端在哪 —— 部署前必须知道的一件事

**本仓库是纯前端仓库**，`routes/`、`models/`、`services/` 目录下只剩 `__pycache__`，没有 `.py` 源码。
前端所有请求都走 `src/api.js` 里的 `baseURL: '/api'`（相对路径，且 `withCredentials: true`），因此：

- **开发时**：由 Vite 把 `/api` 代理到 `http://localhost:5000`（见第 4 节）。
- **生产时**：必须有一个 Web 服务器（Nginx 等）把 `/api` 反向代理到后端，否则页面能打开、接口全 404。

本机 `127.0.0.1:5000` 上确实有一个 Flask 在跑（`server: Werkzeug/3.1.9 Python/3.15.0`），
它的源码在工作区之外的独立目录，**不属于本仓库**，重新部署后端时别在本仓库里找 `app.py`。

### 2.4 前端不需要环境变量

`src/` 里没有任何 `import.meta.env` / `VITE_` 使用，也不存在 `.env` 文件。
后端地址靠**同源的 `/api` 路径 + 代理**决定，所以**切环境不用重新构建**，改服务器配置即可。

## 4. 第三步（开发模式）：本地跑起来

```powershell
cd C:\Users\ccgg5\Desktop\wenya\frontend
npm.cmd run dev
```

**实测预期输出：**

```text
  VITE v5.4.21  ready in 9763 ms

  ➜  Local:   http://localhost:3000/
  ➜  Network: use --host to expose
```

打开 <http://localhost:3000/> 即可看到首页。改 `.vue` 文件会热更新，不需要重启。

### 4.1 这条命令实际做了什么

`vite.config.js` 的 `server` 段决定：

```js
server: {
  port: 3000,
  proxy: { '/api': { target: 'http://localhost:5000', changeOrigin: true } }
}
```

即：`http://localhost:3000/api/xxx` → 转发 → `http://localhost:5000/api/xxx`。
**实测代理链路是通的**（后端在跑的前提下）：

```powershell
curl -i http://localhost:3000/api/works
# HTTP/1.1 404 NOT FOUND
# server: Werkzeug/3.1.9 Python/3.15.0     ← 响应头来自 Flask，证明请求已穿过 Vite 代理
```

这里的 404 是**后端**给的（该路径需要登录或不存在），不是 Vite 给的 —— 前端与后端的联通本身没问题。

### 4.2 端口冲突 / 想换端口

3000 被占用时 Vite 会自己往上找端口（3001…），此时**代理仍生效**，只是地址变了。想固定端口：

```powershell
npm.cmd run dev -- --port 3010
```

或改 `vite.config.js` 的 `server.port`。

### 4.3 局域网 / 手机 / 虚拟机访问

默认只监听 `localhost`（实测 `netstat` 显示 `[::1]:3000`，仅 IPv6 回环）。要让同事的手机访问：

```powershell
npm.cmd run dev -- --host 0.0.0.0
```

然后用本机局域网 IP 访问，例如 `http://192.168.1.20:3000`。

> **注意**：`--host` 只暴露前端页面。此时页面里的 `/api` 仍由**这台开发机**上的 Vite 代理到 `localhost:5000`，
> 所以那台机器上必须同时有后端在跑；后端在别的机器上时，改 `vite.config.js` 里的 `proxy.target`。
> 开发服务器不是安全边界，公司/公共网络上用完就 `Ctrl+C` 关掉。

### 4.4 停止

`Ctrl+C`。Windows 上若端口残留：

```powershell
netstat -ano | findstr :3000      # 找到 PID
taskkill /PID <那个数字> /F
```

})

## 7. 第六步：正式部署

生产环境有两条硬性要求，缺一必坏：

1. **SPA history 回退** —— 所有非文件、非 `/api` 的请求都要返回 `index.html`。
   因为 `src/router.js` 用的是 `createWebHistory()`，用户刷新 `https://域名/writing/123` 时服务器上并没有这个文件。
   回退没配的典型症状：**首页能进，刷新子页面 404**。
2. **`/api` 同源反向代理到后端** —— 前端写死了相对路径 `/api` 且带 Cookie（`withCredentials: true`），
   同源代理可以同时避开跨域和 Cookie 的 `SameSite` 问题。

### 方案 A：Nginx（推荐）

把 `frontend/dist/` 整个目录拷到服务器，例如 `/srv/wenya/dist`（Windows 上放 `C:/www/wenya/dist`）。

```nginx
server {
    listen 80;
    server_name wenya.example.com;      # 换成你的域名；本机测试可写 localhost

    root  /srv/wenya/dist;              # Windows 用正斜杠: C:/www/wenya/dist
    index index.html;

    # 1) 静态资源：hash 文件名，可长期缓存
    location /static/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # 2) 后端接口：转发到 Flask
    location /api/ {
        proxy_pass http://127.0.0.1:5000;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # AI 评分很慢：src/api.js 的超时是 60s，这里必须 ≥ 60s，否则用户看到 504
        proxy_connect_timeout 10s;
        proxy_send_timeout    90s;
        proxy_read_timeout    90s;
        proxy_buffering off;            # 若后端将来改流式输出，必须关
    }

    # 3) SPA 回退：index.html 本身绝不能缓存，否则发版后用户拿旧包
    location / {
        try_files $uri $uri/ /index.html;
        add_header Cache-Control "no-cache";
    }

    # 4) 压缩
    gzip on;
    gzip_min_length 1024;
    gzip_comp_level 6;
    gzip_types text/plain text/css application/javascript application/json image/svg+xml;
}
```

改完配置的检查与生效顺序（不要直接 reload）：

```bash
nginx -t                 # 语法检查，必须显示 successful
nginx -s reload          # 或: systemctl reload nginx
```

HTTPS（面向未成年人的站点实际应当启用）：`certbot --nginx -d wenya.example.com`，
成功后确认 `listen 443 ssl` 与 `server_name` 一致，`/api` 走的是**同源相对路径**，无需再改前端。

### 方案 B：Windows 上不想装 Nginx —— 用 IIS

1. 安装 IIS + **URL Rewrite** 模块（缺 URL Rewrite 时 SPA 回退规则无效，会 404 或 500.19）。
2. 新建站点，物理路径指向 `C:\www\wenya\dist`。
3. 站点根目录放 `web.config`：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
  <system.webServer>
    <staticContent>
      <remove fileExtension=".svg" />
      <mimeMap fileExtension=".svg" mimeType="image/svg+xml" />
    </staticContent>
    <rewrite>
      <rules>
        <clear />
        <rule name="SPA Fallback" stopProcessing="true">
          <match url=".*" />
          <conditions logicalGrouping="MatchAll">
            <add input="{REQUEST_FILENAME}" matchType="IsFile" negate="true" />
            <add input="{REQUEST_FILENAME}" matchType="IsDirectory" negate="true" />
            <add input="{REQUEST_URI}" pattern="^/api/" negate="true" />
          </conditions>
          <action type="Rewrite" url="/index.html" />
        </rule>
      </rules>
    </rewrite>
  </system.webServer>
</configuration>
```

4. `/api` 反代用 **ARR for IIS**，或更省事：**让 Flask 自己挂前端静态目录**（方案 C）。

### 方案 C：前端产物交给后端托管（最省事，单机小流量够用）

把 `dist/` 拷到后端项目里，由 Flask 直接提供静态文件并做回退（示意，需在后端仓库里改）：

```python
app.static_folder = 'dist'
app.static_url_path = '/static'

@app.route('/', defaults={'p': ''})
@app.route('/<path:p>')
def spa(p):
    if p.startswith('api/'):
        abort(404)
    return send_from_directory(app.static_folder, 'index.html')
```

优点：一个进程、一个端口、天然同源，`/api` 不用代理。缺点：静态文件吞吐不如 Nginx，发版要重启后端。

### 方案 D：临时演示（明确不要用于正式环境）

```powershell

python -m http.server 8080
```

`http://localhost:8080/` 能打开首页，但有两个硬伤：**没有 SPA 回退**（刷新 `/writing` 直接 404）、
**没有 `/api` 代理**（所有接口失败）。只适合快速看一眼产物，或配合第 6 节的 `preview` 使用。

### 部署到子目录（如 `https://a.com/wenya/`）

前后要一致地加前缀：

1. 构建时带 base：`npm.cmd run build -- --base=/wenya/`

3. `/api` 反代仍按后端真实前缀配置（后端是 `/wenya/api` 就代理到 `/wenya/api`）。

## 9. 常见问题排查

| 症状 | 根因 | 处理 |
| --- | --- | --- |
| `无法加载文件 ...npm.ps1，因为在此系统上禁止运行脚本` | PowerShell 执行策略 `Restricted`（本机实测生效值） | 见第 1 节：用 `npm.cmd`，或 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
| PowerShell 里 `cd x && npm run dev` 报「&& 不是有效语句分隔符」 | PS 5.1 不支持 `&&` | 用 `;` 或分行；或改用 cmd |
| `npm run dev` 起来后端口是 3001 不是 3000 | 3000 被别的进程占用 | `netstat -ano \| findstr :3000` → `taskkill /PID x /F`，或 `--port 3000 --strictPort` 让它直接报错而不是漂移 |
| 页面打开白屏，Console 报 `/static/index-xxx.js` 404 | 部署到子目录却没配 `base`；或只拷了 `index.html` 没拷 `static/` | 见 5.2；确认 `dist/static/` 已随产物一起上传 |
| 首页正常，**刷新子页面 404** | 服务器没配 SPA history 回退 | Nginx `try_files $uri $uri/ /index.html`；IIS 装 URL Rewrite + 第 7 节规则 |
| 页面能开，接口全挂（404 / 502 / Network Error） | `/api` 没代理到后端，或后端没起 | 开发：确认 5000 端口有进程 + 检查 `vite.config.js` 的 `proxy.target`；生产：检查 Nginx `location /api/` 与 `nginx -t` |
| AI 评分转圈很久后报 504 / 超时 | Nginx 默认 `proxy_read_timeout 60s`，而前端超时也是 60s | 按方案 A 把 Nginx 超时调到 ≥ 90s |
| 发版后用户看到的还是旧页面 | `index.html` 被浏览器/CDN 缓存 | 给 `index.html` 加 `Cache-Control "no-cache"`，`/static/` 才做长期缓存（hash 文件名已保证内容变更即换名） |
| 浏览器标签图标请求 `/vite.svg` 拿到的是 HTML | **`frontend/public/` 目录不存在**，而 `index.html` 引用了 `/vite.svg`；Vite 回退返回 index.html（实测 `text/html`，590 字节） | 纯外观问题，不影响功能。要修：放一个 `frontend/public/vite.svg`，或删掉 `index.html` 里那行 `<link rel="icon">` |
| 依赖装不上 / node_modules 状态混乱 | lock 与本地不同步、缓存损坏 | `rmdir /s /q node_modules ; del package-lock.json`(慎用，会丢版本锁定) 之后 `npm.cmd install`；想严格按锁安装用 `npm.cmd ci` |
| 构建时报 Node 版本相关的语法错误 | Node 低于 Vite 5 要求 | 升级到 Node 18+（本机 v24.21.0 实测正常） |
